# epoku 開発引き継ぎ

基準: 2026-11-05 / アプリ v0.2.0。アプリ本体は `app/`、会議に基づく企画資料はルートの `docs/` にあります。

最新のMVPたたき台は [mvp.md](mvp.md) です。この引き継ぎは、MVPをすべて満たしたという報告ではなく、現在動くプロトタイプと残りの開発項目を渡すものです。

## まず全員で確認する

```bash
git clone https://github.com/kaito-0827/google-hackathon.git
cd google-hackathon/app
npm ci
npm run dev:all
```

http://127.0.0.1:5188/ を開きます。APIキーは不要です。Node.js 24推奨。Windows・macOS・LinuxのいずれでもWeb版を開発できます。AndroidのAPK作成にはJDK 21とAndroid SDK 36が別途必要です。

## 会議の仕様と現在の違い

- **Google Earth系の3D:** 標準画面はGoogle EarthではなくOSMを使った都市模型。Google 3D地図への接続口は別にある。窓や樹冠は見た目の表現で実測ではない。
- **アプリ内経路:** 現状の「行き方」は外部Googleマップを開く。会議で想定したアプリ内の経路・日陰優先ルートは未実装。
- **AI空席予測:** ルール推定を実装。Geminiは説明文のみ。学習済みAI、実際の空席観測として説明しない。
- **投稿の共有:** 初期状態は端末内のみ。チーム共通の投稿にはFirebaseの設定と検証が必要。
- **ピンの色分け・詳細条件:** 現状は種類・選択状態による表示。空席確率による緑／黄／赤の色分け、「座れそう」の閾値絞り込み、「トイレ近く」の条件は未実装。
- **暑さによる空席補正:** `wbgt.ts` はあるが、`App.tsx` は予測へ `wbgt: null` を渡している。暑さ×日陰の係数を中核の予測へ接続し、変化を確認する作業が必要。
- **Geminiの確率補正:** 現状は理由文のみ。MVPたたき台にあるGeminiによる数値補正は未実装で、採否と再現性をチームで確認する。
- **PWA・通知:** マニフェストとオフライン用キャッシュはあるが、OSごとのインストール・オフライン再訪は未検証。健康連携・バックグラウンド通知・LINE通知は未実装。
- **行政連携:** 送付・集約レポート・進捗連携は未実装。

## 優先する開発タスク

### P0: 全員が同じものを動かせる

- [ ] メンバー全員がクローンしてAPIなしで起動する。
- [ ] Android実機で、3D・時刻変更・検索・投稿・再起動後の保存を確認する。
- [ ] チームでアクセスできるWebの公開先を決める。既存のCodexデモURLは所有者向けの制限があり、GitHubの共同開発権限とは別。
- [ ] Firebaseのルールをエミュレーターで確認してから、共有の読み書き・自分の投稿の取消・他人の投稿の保護を確認する。

### P1: ハッカソンで見せる中核を仕上げる

- [ ] Google Maps / Gemini / Weatherのうち、発表に使うAPIを選んで実接続を確認する。全部の導入を前提にしない。
- [ ] みなとみらいの数地点で日陰・席数・座れるかを観察し、日時と条件を記録する。
- [ ] アプリ内の経路表示を実装し、外部マップへ飛ばす現状との差を解消する。
- [ ] 空席確率によるピンの色分け、M5の詳細条件、暑さ×日陰の予測への接続を仕上げる。
- [ ] 実投稿と推定値の説明、デモ天気・仮定した高さの表示を、第三者が誤解しないか確認する。
- [ ] サービスワーカーの更新・オフライン再訪・スマホへの追加を確認する。

### P2: 中核が通った後で判断する

中核が通ったら、MVPのShould（空席確率の時間推移、簡易の休憩提案、Geminiの一言説明）をチームで判断する。LINE・健康データ連携・行政連携など、`mvp.md` のWon'tにある機能は今回の中核へ追加しない。

## API設定で迷わないために

- アプリが読む設定は **`app/.env`**。`app/.env.example` から必要な設定だけ作る。
- `VITE_` はブラウザーへ渡る。`GEMINI_API_KEY` と `GOOGLE_WEATHER_API_KEY` はサーバー専用。
- Google / Firebaseの既存個人プロジェクトや秘密鍵は、このリポジトリには移していない。チームのプロジェクトを使う。
- Node APIはローカル開発用。静的な `dist/` だけを置いてもGemini / Google Weatherは動かない。本番の認証付きAPIを作る場合は別タスクにする。
